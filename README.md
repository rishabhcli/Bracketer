# Bracketer

Bracketer is a native SwiftUI iPhone camera app for bracketed photography. It captures bracketed exposure sequences, provides a camera-focused shooting UI, and includes an in-app review flow for the latest sequence.

## Requirements

- Xcode 26.2 or newer
- iOS 26.2 simulator or device support

## Project layout

- `Bracketer/`: app source
- `BracketerTests/`: unit tests using Swift Testing
- `BracketerUITests/`: UI tests using XCTest
- `Bracketer.xcodeproj/`: Xcode project
- `docs/ARCHITECTURE.md`: capture, planning, settings, review, capability, and observability notes

## Local development

Inspect build settings:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild -project Bracketer.xcodeproj -scheme Bracketer -showBuildSettings
```

Build and test with `xcodebuild`:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild test \
  -project Bracketer.xcodeproj \
  -scheme Bracketer \
  -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.4.1' \
  -parallel-testing-enabled NO \
  -maximum-concurrent-test-simulator-destinations 1 \
  CODE_SIGNING_ALLOWED=NO
```

If that simulator is unavailable, discover a local destination with `xcrun simctl list devices available` and rerun using its simulator id:


## Review sequence contract

`BracketReviewSequence` is the pure model behind review selection and summary state. It can represent complete and partial bracket sequences, clamps selected indexes, tracks the requested RAW/processed representation, marks missing planned shots, labels metadata availability, identifies the closest-to-zero exposure as the best-exposure candidate, and supports deterministic deletion for UI tests. Simulator-only clipping labels are intentionally named as simulated risk, not physical pixel analysis. The Photos-backed `ImageViewer` accepts the same sequence contract for completed live captures, so EV labels come from the bracket plan and saved asset order instead of positional guesses. When Photos resources and EXIF properties load, the viewer updates the selected shot summary with actual file representation and metadata availability.

## Bracket manifest contract

`BracketManifest` is the local JSON-ready sequence export model for future HDR merge, exposure fusion, deghosting, sidecar metadata, and professional workflow handoff. ## App Intents

`OpenBracketerIntent` exposes the first Siri/Shortcuts/Spotlight-facing action. It opens the app into a camera workflow with a destination and bracket preset, records the handoff through `BracketerAppIntentRouter`, and publishes shortcut phrases such as "Prepare a bracket in Bracketer." The camera shell exposes the latest handoff through the hidden `camera.appIntent.lastHandoff` probe so routing can be tested without pretending the app can capture photos in the background. `BracketerShortcutTileInventory` exposes the 10-of-10 shortcut tile count, deferred intent names, and no-headroom boundary through `camera.appIntent.shortcutInventory`. `PrepareTimedBracketCaptureIntent` adds the timer-prepared capture handoff: it opens the camera with a selected bracket preset and timer applied, but still requires the photographer to review and start capture in the app. `OpenLatestBracketProjectIntent` records a latest-review handoff through the same router and opens the app to the latest saved project when one exists; if no project exists, the provider opens the camera with no fake review claim. It is intentionally not added as an extra shortcut tile while the app is at the 10-shortcut cap. `SummarizeLatestBracketProjectIntent` is the first project-query shortcut: it reads the persisted latest project through `LatestBracketProjectSummaryProvider` and returns a text summary with the same metadata-only final-output action plan used by export surfaces. `ExportLatestBracketManifestIntent` returns only the latest saved `BracketManifest` JSON as an `IntentFile`, defaults to metadata-only redaction, can explicitly include recovery identifiers, and does not export raw image bytes, fetch Photos resources, decode RAW files, emit final rendered output, or count physical proof; it remains a deferred App Intent rather than an extra App Shortcut tile. `ExportLatestBracketProjectBundleIntent` reads the latest persisted project and returns a redacted metadata bundle as an `IntentFile`, with explicit privacy and filename parameters for metadata-only, recovery-identifier, Project ID, Dated summary, or Privacy audit exports, and the typed file-provider result carries the final-output action-plan summary. `ExportBracketProjectBundleIntent` does the same for a selected `BracketProjectEntity`, so Shortcuts can export a chosen project instead of only the latest one. `ImportBracketProjectBundleIntent` is the matching Shortcuts import surface: it accepts a project bundle `IntentFile`, applies a keep-both/replace/reject duplicate policy, and delegates to `FileBracketProjectStore.importArchiveText` so metadata-only archive redaction, import validation, and final-output action-plan accessibility stay identical to Settings imports. `ExportBracketerPhysicalResultBundleCommandPlanIntent` gives Shortcuts a copy/share-only physical lab command-plan file for a selected runbook scenario, including an optional safe `Result Bundle Path`, and never runs those commands; `ExportBracketerPhysicalProofTemplateIntent` turns compact xcresult summary JSON into a seeded preview-only physical proof template file while keeping real hashes/device evidence as placeholders; `ExportBracketerPhysicalLabWorkspaceIntent` returns a Markdown lab workspace that combines the runbook, command plan, output paths, expected artifacts, and seeded template in one file; `PreviewBracketerPhysicalLabWorkspaceIntent` previews that workspace manifest as a checklist without counting proof; `ExportBracketerPhysicalLabReviewHandoffPackageIntent` returns the split package-manifest/workspace/command-plan/template/output-paths/checklist archive for handoff review. `BracketProjectEntity` and `BracketProjectEntityQuery` expose persisted project records as a small AppEntity surface backed by the same local project search model, including the computed action-plan summary in accessibility and text search without exposing private Photos identifiers. CoreSpotlight continuation is wired through `BracketerSpotlightHandoff`, which resolves a hashed Spotlight item identifier back to the saved project and records the same review handoff path. The app now consumes review handoffs by loading the selected or latest project, marking it current, reconstructing its manifest-backed sequence, and presenting `BracketProjectReviewHandoffView`.

`QueryBracketProjectsIntent` extends the project-query surface from latest-only summary to filtered saved-project search. It accepts a text term plus project collection, project facet, captured-day, lens-id, and location-policy-id parameters, routes through `BracketProjectLibrarySearchProvider` and `FileBracketProjectStore.librarySearchRoute(searchText:smartCollectionKind:facetFilter:capturedDay:lensID:locationPolicyID:)`, and returns matching `BracketProjectEntity` values while preserving the same privacy-safe search corpus used by the Settings library sheet.

## Settings persistence

`SettingsStore` persists camera preferences through `UserDefaults` and supports an injectable defaults suite for tests. Persisted numeric values are normalized on load and write: focus peaking intensity is clamped to the slider range, EV step is snapped to supported UI steps, and bracket shot count is snapped to 3, 5, or 7. The generated-project-note storage preference is persisted here too, defaults off, and is mirrored into `CameraController` before project sidecars are written.
